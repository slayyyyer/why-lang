Why is a small page language for the JVM. A page is a .why file in a folder; the server compiles it on request. No router, no build step, no framework — one jar and a directory.

Why a new language?

Because writing a page should mean writing a page.

Templates with teeth

Every mustache evaluates a real expression.

Dropping files is the API

Copy a page into the folder and it is live.

Keep it small

The page is the unit.

Three sections, one file, one URL. Everything else is an import away — and imports are just more files.

01

A page is a file

imports:, controller:, view:. Drop it in the folder and the URL exists. No route table to update.

02

Ruby's shape

Defs, blocks, unless, truthiness, string interpolation. No classes, no gems, no Rails.

03

Views with teeth

Handlebars-flavored mustaches that evaluate real expressions. Escaped by default, partials included.

04

SQLite in the box

db.query, db.get, db.exec with bound parameters. A first-run schema.sql makes a folder self-contained.

05

Errors you can read

file:line, the offending source line and a caret, the partial or import chain, and did-you-mean hints.

06

Check before you serve

why check compiles every page, reports imports, partials, duplicate defs, undefined calls and URL collisions, then prints a page map.

Status: a proof of concept. M0–M2, deliberately small. No package manager, classes, bytecode, sandboxing or production hardening. The interesting part is how far the page model goes before it needs a framework.

Two commands to a running page.

JDK 21 and Maven, then build the jar and point it at a folder. The demo site is included.
